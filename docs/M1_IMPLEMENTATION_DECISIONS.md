# M1 implementation decisions

These choices resolve the open questions in Appendix A of the finalized architecture specification. They deliberately define a small, testable subset; they do not claim general semantic equivalence.

| Topic | M1 decision | Reason |
| --- | --- | --- |
| Expression typing | Keep the AST nodes free of inferred type annotations. The validator computes a deterministic type table keyed by AST node ID and reports it with the validation result. Literal kinds remain explicit. | Avoids stale inferred types being copied between adapters or treated as source meaning. |
| Expression grammar | Parse expressions into AST nodes using precedence: parentheses; unary `+`, `-`, `!`; `*`, `/`, `%`; `+`, `-`; numeric comparisons; equality; `&&`; `||`. Comparisons cannot chain. Only these operators and `int`, `double`, `char` literals/references are supported. | One parser and type checker can serve both adapters and the generator. The existing Python expression grammar is not reused as the M1 language grammar. |
| Graph to block semantics | Require one Start and one End. A decision's true and false paths must have one unique nearest common post-dominator. Convert the paths before that join into the two `IfStatement` blocks, then continue at the join. Reject cycles, cross edges, paths that bypass the join, and joins that cannot be uniquely established. Nested decisions are allowed only when the same rule can recursively form unambiguous regions. | Makes branch structure explicit while preventing a graph layout heuristic from inventing control flow. |
| C I/O | Use `scanf` with checked return counts: `%d` for int, `%lf` for double, and ` %c` for char. Emit prompts as escaped string literals. Print ints with `%d`, doubles with `%.17g`, chars with `%c`, and literal messages with `%s\n`. | Defines deterministic formatting and avoids treating user text as a format string. M1 char input is one character; string variables are unsupported. |
| Canonicalization | Compare ordered statements and expressions structurally. Ignore AST IDs and provenance; resolve symbols by declared identifier name and type. Do not reorder statements, fold expressions, or apply algebraic rewrites. | Independently-authored inputs cannot be expected to share source IDs. Conservative structural comparison returns unknown when correspondence is not established. |
| Approval freshness | Bind approval to project ID, semantic revision, both source revision numbers, canonical AST fingerprint, and adapter/canonicalizer/validator/generator versions. Any mismatch makes it stale. Presentation revision is excluded. | Monotonic revisions and semantic content identify what the user approved; timestamps alone do not. |
| Import policy | Schemas are strict: reject unknown fields, unsupported versions, duplicate IDs, and broken references. No implicit migration in M1. | Prevents a newer or corrupt project from being silently truncated. |

These decisions are implementation contracts for M1, not evidence that the corresponding modules or checks already exist. They should be revisited only by changing the contract, fixtures, and tests together.

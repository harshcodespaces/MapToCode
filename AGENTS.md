# MapToCode — project instructions for Codex

## Product vision
MapToCode is a beginner-friendly website that helps people turn flowcharts into Python code. The first deliverable is a polished website and a usable browser-based prototype. The longer-term product should let users create flowcharts visually, see the generated Python code, download it, and eventually upload a photograph of a hand-drawn flowchart for recognition.

## Working rules
- Work inside this existing repository. Inspect its files before editing anything.
- Do not delete, reset, or overwrite existing user work. If you need to replace or restructure files, explain why and ask first.
- Work in small, testable milestones. Start by reporting what is already here and proposing the smallest useful next step, then implement it.
- Explain terminal commands and important code changes in beginner-friendly language.
- Prefer clear, readable code over clever abstractions.
- Use JavaScript, not TypeScript, unless the user explicitly requests TypeScript.
- Use Next.js App Router, React, semantic HTML, and ordinary CSS. Use Node.js/npm to run the web application.
- The primary target language generated by MapToCode is Python.
- Do not use Streamlit.
- Do not add external APIs, hosted backends, third-party website embeds, remote scripts, remote fonts, remote images, analytics, or tracking. The app should work locally on the user's computer without depending on any external service at runtime.
- Use local assets and CSS for visuals. Avoid adding npm packages unless they provide clear value; explain any package before adding it. Do not introduce a visual-editor dependency without explaining the trade-offs first.
- Do not claim a feature works unless you implemented and tested it. Clearly label any placeholder feature.
- Never execute generated Python code on the server. Generate source text for preview/download; execution, if ever added, must be isolated and designed separately.
- Validate node types, edges, and user-entered values before generating code. Do not insert arbitrary user text into executable Python syntax.
- Keep secrets, tokens, and local machine credentials out of source control.

## Product UX and design direction
- Build a real, polished software product, not a generic form or a Streamlit-like demo.
- Brand: MapToCode.
- Visual direction: modern developer tool; uncluttered layout, clear hierarchy, refined spacing, tasteful color, readable typography, accessible contrast, responsive layout, and useful empty states.
- Do not imitate any existing brand exactly.
- Avoid external stock photos or web-dependent decorative assets. Prefer original UI, icons made with CSS/inline SVG, and diagrams rendered in the app.
- Homepage should communicate the product in a few seconds and have a clear “Open Workspace” call to action.
- Workspace should prioritize a visual flowchart canvas and a generated Python preview.

## Functional product roadmap
### Milestone 1 — website foundation
- Inspect the current repo and identify the actual Next.js app directory (possibly `web/`).
- Ensure the app starts with the project's existing package manager and scripts.
- Build a polished responsive homepage with navigation, hero section, a small visual flowchart illustration made locally, clear benefits, a “How it works” section, and an “Open Workspace” CTA.
- Create a workspace page/route with a clear canvas area and code-preview panel. These can initially be a functional prototype, but clearly identify anything not implemented yet.
- Do not add authentication, a database, payments, deployment, or third-party integrations.

### Milestone 2 — local visual flowchart editor
- Support node types: Start, Input, Process, Decision, Output, and End.
- Let users add nodes, select a node, edit its label/value, remove nodes, and define connections between nodes. Prefer intuitive canvas interactions; if real drag-and-drop or edge rendering requires a dependency, explain it and seek approval before adding it.
- Provide helpful defaults and validation messages.
- Store the current diagram in browser state initially; persistent accounts/storage are out of scope.

### Milestone 3 — Python code generation
- Convert a validated, structured flowchart representation into readable Python source.
- Support a small, documented subset first: Start, Input, Process (limited safe assignments), Decision, Output, End.
- Show a live or button-triggered code preview and a local download of a `.py` file.
- Add basic tests for supported constructs and invalid diagrams.

### Milestone 4 — hand-drawn image recognition (later)
- First document a design before implementing it. Do not pretend a photo-upload button recognizes drawings until actual image processing exists.
- Evaluate a local Python computer-vision pipeline; do not call external vision APIs unless the user later explicitly approves that change.

## Done criteria for each milestone
- Run the relevant available lint/build/test commands.
- Fix errors caused by your changes.
- Summarize files changed, features implemented, commands run, and anything unfinished.
- Provide the exact command to start the app from the correct directory.
